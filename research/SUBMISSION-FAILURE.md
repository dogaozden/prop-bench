Live-bundle files can be changed after cutoff and **are not official submissions**; the timed stdout/command and checkpoint chronology, rather than file modification times alone, establish the pre-cutoff proof. The owner did not seal canonical proof bytes in a checkpoint because the directory read failed, so byte identity at every later instant cannot be inferred from owner checkpoint data alone.

The contestant kept draft JSON files inside `proofs/`. The frozen goal named the canonical graded filename, but did not clearly explain that an unrelated draft would invalidate capture of every selected proof. The all-or-nothing harness behavior turned that workspace choice into a missing result. `readSubmissionEntries` scans names in sorted order and throws on the first unselected JSON name before returning any canonical file; checkpoints then record an empty submission list. This explains the observed `candidate-agent1.json` error even while `g2-2100030.json` existed and passed strict validation. Checkpoint verdicts were not shown to the contestant, so the repeated rejection was not available as feedback. No inference about whether the agent would have removed the drafts with feedback is warranted.

**Subsequent source repair, excluded from this frozen campaign:** subscription checkpoints now record and ignore safe regular JSON drafts while independently capturing exact selected theorem filenames through the existing safe-file and pinned-referee checks. Keep unsafe directory ancestry, symlinks, hardlinks, special files, size violations, and malformed selected files subject to their existing protections. The revised GOAL explicitly puts scratch proofs in `tools/` and asks for a saved baseline before further search. Manual historical import remains strict. The repair is versioned by a new source/evaluator identity and must be frozen in a new campaign; it does not change this campaign. Do not retroactively import this run's live bytes or change its loss 1.

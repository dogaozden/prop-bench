# Publication preparation, September 25, 2026

The publication is a reproducible experiment in formal proof compression.
Frontier measures a tool-using system; Unaided measures a fresh model session
without external computation or verifier feedback. The two conditions stay
separate. All new inference uses the existing native Codex subscription.

## Acceptance

- A current native Codex client with exact model, effort, binary identity and
  tool-surface checks; no Claude or API-key fallback.
- A validation-only Docker executable, with no theorem generator or planted
  proof reconstruction command available to contestants.
- Frontier v2 checkpoints retain independently verified improvements before
  the deadline, even if the final working file regresses. Sealed finalization
  cannot accept later work.
- The local owner console stays on loopback, rejects foreign browser origins,
  and preserves historical data. The public site is static and has no command
  execution or account endpoints.
- A preregistered full v2 census: 24 items, two independent Unaided repetitions,
  one fresh Frontier pass, one cumulative Frontier pass from the corresponding
  fresh result. Each singleton run gets 900 seconds; Frontier gets 128 tool
  calls. Requested model is gpt-6-astra at xhigh, normal service tier. All exact
  identities and dispatch ordering are recorded in the campaign manifest.
- Campaign failures remain visible; missing, invalid and interrupted outcomes
  cannot disappear from aggregate denominators. No automatic retry of an
  uncertain or started session. New rounds have new identities.
- Public results are independently replayed before export, with raw lengths,
  coverage, budgets, lineage, source hashes and limitations. The export omits
  account data, host paths, raw native sessions and private model reasoning.
- The public page works on desktop/mobile and a website subpath, with readable
  formal proofs, accessible controls and downloadable evidence.
- Required tests/builds, physical sandbox controls and live native checks pass;
  completed changes are committed and pushed. Publication assets are ready for
  the owner's website; no external deployment or repository visibility change
  is part of this task.

## Work boundaries

Native compatibility, checkpoint/deadline controls, validation-only runtime,
local Tracks controls, campaign orchestration, static publication site and
independent methodological review proceed as distinct workstreams. The main
agent integrates and accepts their results. Evaluation source is frozen before
the official campaign; later fixes require a new campaign identity.

Existing September 8 results are historical pilots. The previous full CLI in
Frontier is not evidence for the new validation-only runtime. Pars are known
achievable lengths, not optimal lengths or difficulty certificates. Two trials
are a small repeatability check, not a robust uncertainty estimate. Cumulative
results include both inherited artifacts and an additional time allowance.
